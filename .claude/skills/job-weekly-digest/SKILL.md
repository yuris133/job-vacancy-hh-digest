# Дайджест вакансий по профилю кандидата

## Входные данные (читай первым)

1. `candidate-profile.md` в рабочей папке — профиль кандидата (роль, отрасль, достижения с цифрами, города, антитребования «не подходят»). Файл обязателен: если его нет или он пуст — попросите пользователя заполнить по шаблону, не выдумывайте профиль.
2. `tg-credentials.json` в той же папке (если существует): `{"bot_token": "...", "chat_id": "..."}`.

## Окно поиска

Только вакансии, опубликованные за последние 7 дней от даты запуска. Города — из профиля кандидата (`cities`); остальная Россия — только при очень сильном совпадении.

## Порядок работы

1. **Поиск**: WebSearch и/или HTML-страницы hh.ru (сортировка `order_by=publication_time`), зеркала careerist.ru / dreamjob.ru — по направлениям из профиля (список `roles`). API api.hh.ru НЕ использовать: с апреля 2026 он отдаёт 403 анонимам.
2. **Проверка активности — ОБЯЗАТЕЛЬНЫЙ шаг**: прямая загрузка карточки каждой вакансии шорт-листа (WebFetch). «Активна» = страница отдаёт описание и кнопку «Откликнуться», нет пометки «в архив». Кэш агрегаторов врёт по датам. Итог не содержит архивных.
3. **Ранжирование**: приоритет = совпадение с профилем → уровень роли → вилка → минимальные риски. Совпадение в % — экспертная оценка (указать в таблице).
4. **Обновление файлов** (не удалять и не переименовывать существующие):
   - `summary-table.md` — дописать сверху секцию «## Обновление [дата]» с таблицей активных вакансий (старые секции не трогать);
   - `summary-table.csv` — дописать строки ниже имеющихся; колонки: Приоритет;Компания;Позиция;Город;Дата публикации;Статус;Вилка;Совпадение %;Партия;Ссылка (разделитель `;`). Новая партия получает значение «Партия» = дата прогона. В статусы ставить только проверенные по прямым страницам.
5. **Сводка для Telegram** (короткая, ~10 строк): топ-5 активных (или «активных не найдено»), отметка о подтверждённых активных из прошлых недель, одна строка о рынке недели.
6. **Отправка в Telegram**: прочитать `tg-credentials.json`, POST `https://api.telegram.org/bot<TOKEN>/sendMessage` с `chat_id`, `text`, `disable_web_page_preview: true`. Токен нигде не выводить и не записывать в таблицы/отчёты. Нет файла или сбой → сохранить сводку в файл `[дата]—дайджест—отчёт.md` и сообщить пользователю, что повтор отправки по его команде.

## Стиль дайджеста (см. templates/telegram-digest.md)

- Нумерованный список: позиция — компания — город — вилка — дата публикации — ссылка — оценочное совпадение.
- Отдельная строка статистики: найдено/активных/новых.
- Не включать исполнителей вне отраслей кандидата, продажи, монтажников и прочее из «не подходят» профиля. Командировки в зоны боевых действий — не включать в таблицу (можно пометить отдельной строкой).

## Границы

- Работать только в папке проекта; ничего не удалять, не перемещать, не переименовывать. Токены не светить. Отправка в Telegram — только как часть этого дайджеста по команде пользователя.
- По завершении — отчёт: изменённые файлы (с путями), сколько найдено/активных/новых, доставлено ли в Telegram, что дальше.
