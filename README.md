# Job Vacancy Digest (HSE) — еженедельный сбор вакансий вручную

Проект: автоматизация ручного еженедельного поиска вакансий по заданному профилю кандидата с проверкой активности, ранжированием, ведением сводной таблицы и доставкой топ-вакансий в Telegram.

Версия пакета: 1.0 (2026-11-18). Родоначальник: личный проект «Поиск работы» (см. `../` рядом — рабочая папка кандидата).

---

## 1. Что делает проект

Один запуск = один конвейер:

```
профиль кандидата → поиск свежих вакансий (окно 7 дней)
→ проверка каждой карточки по прямой странице (активность!)
→ ранжирование (совпадение → уровень роли → вилка → риски)
→ обновление сводной таблицы (markdown + CSV)
→ топ-5 в Telegram-бот
→ отчёт: изменённые файлы + кто доставлен
```

Запускается вручную раз в неделю (или чаще) — по команде пользователя.

## 2. Почему «проверка активности» обязательна

Поисковая выдача (в т.ч. кэш популярных агрегаторов) отдаёт **снимки вакансий месяцевной давности**, где вакансия уже в архиве. Проект требует для каждой карточки шорт-листа прямую загрузку страницы: «активна» = страница отдаёт описание и кнопку «Откликнуться», без пометки «в архиве». Без этого шага дайджест превращается в рассылку мёртвых ссылок (у нас был такой первый проход — 14 вакансий, все архивные).

## 3. Состав пакета

```
job-vacancy-hh-digest/
├── README.md                          ← вы здесь
├── candidate-profile.md               ← ШАБЛОН профиля кандидата — заполнить из своего CV
├── .claude/skills/job-weekly-digest/
│   └── SKILL.md                       ← скилл для Claude Code (автоматический конвейер)
└── templates/
    ├── summary-table.md               ← формат сводной таблицы вакансий
    ├── summary-table.csv              ← формат CSV (для Excel/Google Sheets)
    ├── telegram-digest.md             ← формат сообщения в Telegram
    └── cover-letter-template.md       ← каркас сопроводительного письма
```

**Что НЕ лежит в пакете и почему:**
- `CV.md` (личные данные кандидата) — вместо этого есть `candidate-profile.md`-шаблон: заполните своими данными.
- Токены Telegram (`tg-credentials.json`, `telegram.env/`) — создаёте свои (см. секцию 5). Никогда не раздавайте чужие токены и не коммитьте свои в публичные репозитории.

## 4. Запуск

### Вариант А — через скилл (Claude Code)
Папку пакета кладёте рядом с рабочей папкой проекта (или к себе в проект) — скилл подтянется, запускаете командой:
```
/job-weekly-digest
```

### Вариант Б — без установки скилла (промпт)
Скопируйте следующий промпт в Claude Code, находясь в папке пакета:

> Запусти скилл из `.claude/skills/job-weekly-digest/SKILL.md`: сделай дайджест свежих вакансий по профилю из `candidate-profile.md` с активностью-проверкой, обнови сводную таблицу и отправь топ в Telegram из `tg-credentials.json`.

### Вариант В — без Claude вообще
Работает и вручную: список свежих вакансий собираете на hh.ru (сортировка по свежести), сверяетесь с форматом таблицы, верифицируете каждую ссылку открытием страницы. Скилл экономит время, но не является единственным способом.

## 5. Настройка с нуля (10 минут)

1. **Профиль кандидата** — заполните `candidate-profile.md` (шаблон внутри): роль, отрасль, ключевые достижения с цифрами, города, «не подходят».
2. **Telegram-бот**: в Telegram → @BotFather → `/newbot` → получите токен вида `123456:ABC...`.
3. **chat_id**: напишите своему боту любое сообщение (например «тест»), затем один раз через Claude (или через `getUpdates`) получите ваш chat_id.
4. **Файл кредов** — создайте `tg-credentials.json` в папке пакета:
   ```json
   { "bot_token": "123456:ABC...", "chat_id": "123456789" }
   ```
5. Проверка: запустите скилл — первое сообщение бота придёт сюда.

## 6. Что обновляется при каждом прогоне

| Файл | Поведение |
|---|---|
| `summary-table.md` | дописывается секция «Обновление [дата]» сверху; старые секции не трогаются |
| `summary-table.csv` | дописываются строки новой партии; колонка «Партия» — дата прогона |
| Telegram | 1 сообщение: топ-5 (или «не найдено») |

## 7. Известные ограничения (важно)

- **API hh.ru закрыт для анонимов** (апрель 2026): `/vacancies` возвращает 403 без одобренного токена приложения. Поэтому проект собирает через HTML-страницы и зеркала (careerist.ru, dreamjob.ru), даты берёт из JSON-LD карточек — api.hh.ru не используется.
- **Capтcha и rate-limit на hh.ru** при серийном обходе: страницы перекачиваются повторно, но источник может времено блокировать; дайджест в такие дни тоньше обычного.
- **Кэш агрегаторов**: та причина секции 2 — сверяйтесь с датой публикации на карточке, не верьте выдаче.
- **Telegram-доступ**: в РФ API Telegram требует VPN/прокси; без туннеля отправка падает с сетевой ошибкой — прогон сохраняется в файлы дайджеста, недоотправка компенсируется при следующем запуске.
- **Автоматика Cloudflare/по расписанию**: в родоначальнике проекта выведена в отдельную папку (`cloudflare-worker/`) по желанию пользователя; в этом пакете — только ручной запуск (см. историю: автоматические кроны в сессии живут ≤7 дней, облачные требуют платного LLM API).

## 8. История и решения проекта

- v1.0 (ноябрь 2026): ручнойweekly-дайджест; hh-API-вариант закрыт (анонимный доступ отменён с апреля 2026); облачный вариант B (Claude API + Cloudflare Worker) — код готов, заморожен без ключа; принято решение работать вручную.
- Дайджесты ведутся с 13.11.2026: 4 прогона, ~40 вакансий, 7 сопроводительных писем.
